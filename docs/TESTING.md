# Testing (para Claude)
Regla de trabajo (TDD, regresión por bug): [CLAUDE.md](../CLAUDE.md). Este doc: cómo se prueba, qué hay y qué falta.

## Cómo diseñamos los tests (TDD con riesgos reales, épica #540)
La cobertura (84 %) no dice si algo vigila el código. Lo que más bugs ha encontrado son las técnicas de esquinas, paridad, datos reales e integración, no los tests de ejemplo con datos inventados. Reglas:
- **Estados alcanzables**: `tests/builders.py` → `Match` juega eventos por la máquina de estados real (`LiveGame`) y devuelve el snapshot; se niega a lo imposible (tiempo hacia atrás, rebote sin tiro fallado, equipo desconocido). `snap()` (dict a mano) queda para fijar un solo campo. Los helpers que antes se importaban de `test_live_core_advice.py` (`OWN`, `RIVAL`, `snap`, `_player`, `engine`…) viven ahí; los tests no se importan entre sí. Ejemplos: `test_live_core_scenarios.py`.
- **Prueba de rojo** (`scripts/red_proof.py`, job `red-proof` del CI, informativo): ejecuta los tests nuevos o modificados contra el código de la base (worktree desechable) en tres suites: **Python** (`tests/test_*.py`, pytest), **Web** (`frontend/src/**/*.{test,spec}.ts(x)`, vitest) y **App live** (`apps/live-android/src/**/*.test.ts(x)` y `scripts/**/*.test.mjs`, vitest), con los mismos patrones que el `include` de cada `vite.config.ts` (un test lo vigila). Debe fallar al menos uno (o no poder importarse la función nueva); el resumen dice el resultado de cada suite. Las de vitest usan el `node_modules` de la rama: sin `npm ci` salen «sin ejecutar». Un PR solo de documentación (`*.md`, `docs/`) no necesita prueba. `--strict` devuelve 1 si no hay prueba; `--needs` dice qué suites traen tests nuevos (el CI instala solo esas). Los e2e de Playwright no entran. Prueba: `test_red_proof.py` (la app con un vitest falso en su `node_modules`). Hasta #610 solo veía pytest: los arreglos de la web y de la app salían «sin tests» aunque los tuvieran.
- **Informe de código duplicado** (`scripts/duplicate_code.py`, job `duplicate-code` del CI, informativo; #452): bloques de ≥ 8 líneas idénticas (sin comentarios, imports ni sangrado; sin tests ni dependencias) en `src/` y los frontends, con el resumen en el panel de cada ejecución. Línea base del 23/10/2026: 65 bloques Python (≈ 1.030 líneas redundantes) y 22 de TypeScript (≈ 255). No bloquea nada; sirve para elegir qué extraer al tocar cada zona. Prueba: `test_duplicate_code.py`.
- **Guarda del lenguaje de staff** (`tests/test_live_core_staff_language.py`, #566): recorre con `ast` todos los textos de `src/live_core` que pueden llegar al staff (sin docstrings) y falla si usan la jerga del análisis —siglas de los cuatro factores, «pts/100», «ajustar al histórico», «neto», «esperado», «índice», «experimental»—: se dice con las palabras del banquillo («lo habitual», «de diferencia», «frente al X % del rival»). Vale para cualquier regla nueva.
- **Checklist de esquinas** (elige las que apliquen; cada bug nuevo añade la suya): frontera de periodo/cuarto y prórroga · determinismo (`PYTHONHASHSEED`, orden, `set`) · vacío/None/cero · FEB **y** FBCYL · idempotencia (evaluar dos veces) · datos que llegan tarde, corregidos o duplicados · ids que cambian de temporada · estados que el motor no puede alcanzar (usar `Match`).
- **Qué no se escribe**: un test por constante o default (tabla `parametrize` de umbrales acordados), el texto exacto de un mensaje salvo en frases críticas (lo demás, por `evidence`), interacciones de mocks que solo repiten la implementación; mocks solo en fronteras (red, Mongo), con fakes (`FakeFeb`) mejor que `MagicMock`.
- **Fases siguientes (aplazadas hasta medir la A)**: propiedades e invariantes con `hypothesis` (#544), nightly de robustez con orden y semillas aleatorias (#545, absorbe #293), biblioteca de partidos raros (#546), `mongod` real y `schemathesis` (#547), spike de mutación (#548).

## Ejecutar
```bash
pytest -q                                   # backend completo (cobertura sobre src/ por defecto, pytest.ini)
# En local solo se ejecutan los tests de lo que se ha tocado (p. ej. `pytest -q --no-cov tests/test_live_core_*.py`); la suite completa tarda ≈ 6 min y la ejecuta el CI de GitHub en cada PR (regla de CLAUDE.md).
pytest tests/test_live_core_*.py -q --no-cov
cd frontend && npm run lint && npm run type-check && npm run test:run && npm run build
python tests/live_vectors/generate.py       # regenerar vectores live tras cambiar live_core
cd tests/pyodide && npm ci && node run_vectors.mjs   # motor dentro de Pyodide
```
Dependencias: `pip install -r requirements-dev.txt` (Render usa solo `requirements.txt`). Tests con marker `ml` (`test_backtesting`, `test_game_prediction`, `test_player_prediction`, `test_predictive`, 2 de `test_regression_formulas`) se **saltan** solos sin `scikit-learn`; en CI corren. Frontend en Windows: si vitest no arranca por el binding de rolldown, `rm -rf frontend/node_modules && npm ci`.

## CI (`.github/workflows`)
`ci.yml`: backend (**en paralelo con `pytest-xdist`**: `python -m pytest tests/ -n auto --dist loadscope`, un proceso por CPU —4 en el runner— y los tests de un módulo juntos para construir sus fixtures de módulo una vez por proceso; hay que usar `python -m pytest` y no `pytest` a secas porque algunos tests importan `from tests.x import y`. **La cobertura (`--cov-fail-under=82`, medida 84 % el 23/10/2026: 4.746 tests en 8 min 45 s en local con `-n auto`) solo se calcula en `main`**; en un PR no se mide, así que un PR puede bajarla y se nota al integrar. Antes: 8 min en un solo proceso; medido en local con 4 procesos, los 3.002 tests tardan 1 min 22 s. Python 3.11, instala `requirements-dev.txt`; base de cobertura medida 77,7 % (primer run de `main` con xdist, 14/10; antes 71,8 %); subir el umbral solo cuando la cobertura mejore de forma estable), frontend (`npm ci`, lint, type-check, vitest, `npm run build`), job `e2e-web` (smoke Playwright, ver abajo), deploy a Render solo en push a `main` (necesita `e2e-web`) con comprobación posterior (`scripts/post_deploy_check.py`, ver OPERATIONS). `live-vectors.yml`: regenera vectores (falla si `git diff`), pruebas de referencia sin `conftest`, vectores en Pyodide.
